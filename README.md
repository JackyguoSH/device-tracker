# kept · 设备总谱

Vite + React 19 + TypeScript 的个人电子设备成本账本。纯静态应用，无服务器、登录或外部运行时请求。十件设备共享时间轴，点击设备或轨道即可在详情弹窗中查看成本曲线与支出记录。

## 构建与运行

```bash
npm ci
npm run dev
npm run build
```

Node.js 20.18+，建议使用提供的 Node.js 22.16。`npm run build` 先执行 TypeScript 检查，再生成 `dist/`。

本地检查生产构建：

```bash
npm run preview -- --port 4187
```

浏览器打开终端打印的地址。开发默认端口 5173；端口占用时 Vite 会选择下一端口。

## 静态部署

将 **`dist/` 内的全部内容** 上传到任意静态托管（Nginx、GitHub Pages、Netlify、Vercel 等）。构建命令为 `npm run build`，发布目录为 `dist`。Vite `base: './'` 支持部署到域名根目录或子目录。没有服务端路由，不需要 SPA 重写规则。请通过 HTTP(S) 打开，不要直接双击 `dist/index.html`。

所有字体、图标与静态氛围背景均本地提供。部署不需要 API 密钥，也不会上传设备记录。

## 默认快照与计算口径

统计日固定为 **2026-11-03**，不会因当前系统日期改变。菜单可临时调整统计日，并可一键返回快照；刷新恢复默认统计日。新增设备默认购入日为当前选定的统计日。

原样复用备份项目的以下四个文件：

- `src/data/devices.ts`：十件原始设备的全部字段、追加明细、备注与归档信息。
- `src/lib/cost-history.ts`：原始成本计算引擎。
- `src/lib/model.ts`：模型、校验、持有天数、日期与金额格式。
- `src/lib/csv.ts`：原始 CSV 编解码及导入校验。

初始结果：在用 8 件、归档 2 件，当前持有投入 **¥43,274.00**，日均合计 **¥23.64/天**。金额先用未舍入数据汇总，最后显示两位小数。

日均 =（购入金额 + 截至该日已发生追加 − 已发生回收）÷ 使用天数。使用日期差，至少为 1 天；明确停用后回收只抵扣成本，不增加天数。年均 = 未舍入日均 × 365，是摊销值，不是年度实际支出。

追加事件来自原引擎解析。`score.ts` 仅把成本历史投影到轨道：购入日追加从原引擎的购入日余额取得，同一天的支出合并成刻度；原始逐项明细保留在事件详情与完整档案中。日期待补充、续保周年估算、明细合计折算等说明与曲线一起显示。**成本计算不按设备名称或 ID 分支。**

AirPods Pro 2 的日均计入已记录的追加投入；HomePod mini_R 为零支出，显示 ¥0.00/天。购入价为 0 表示零支出。

## 使用方式

- **时间线**：默认保留原始十件设备顺序，共享 2020 至统计日的时间尺。持有设备延伸至统计日，归档设备止于归档或显式停用日。竖刻度为追加、空心圆为回收。点击设备再次收回；点击刻度可展开金额、日期与明细，并定位到该日的曲线。
- **排行**：同一批设备行过渡为横条，按成本从高到低排列，支持日均 / 年均。无有效日期的设备置后。切回时间线恢复上次的时间线排序。
- **筛选**：名称、标签、备注、购买渠道、追加明细全文搜索；状态与分类筛选。筛选不改变全账本汇总口径。
- **设备详情**：近一年 / 完整持有期曲线、历史与日均同比、未来一年预测、个人日均目标、全部档案字段。预测固定统计日净投入，假设不再发生追加或回收。编辑与删除位于展开区；删除有确认与撤销。
- **统计**：当前在用组合的 30 天 / 365 天历史趋势、区间变化、年均摊销、持有最长设备、分类投入与占比。回溯的是当前在用组合，归档设备不纳入组合曲线。
- **新增设备**：顶部始终可见，保存后清除筛选并展开新记录。新增、修改、删除、导入均支持最近一次操作的撤销。
- **菜单**：明暗主题、统计截止日、CSV 导入导出。导入先校验完整文件，预览记录数，可按 ID 合并或整体替换；校验错误不会改动账本。导出保留全部 19 列，包含停用日期、个人目标、照片链接与原文换行。
- **手机**：设备名和成本并排，时间轨迹独占下一行；默认完整显示持有期，无需横向滚动。稀疏年份刻度、全宽详情和触控尺寸操作适配竖屏，主导航收进汉堡菜单。

## 存储

设备保存在浏览器 `localStorage` 的 `wuji-score-devices-v1`，主题在 `wuji-score-theme`。与原项目存储键隔离；不会修改原站或备份目录。没有跨设备同步，建议定期导出 CSV。清除网站数据会恢复初始十件设备；存储失败时会保留表单并提示失败，不会假报保存成功。

## 视觉与可访问性

石墨 / 雾白双主题；冷白持有线、少量冰蓝选中态，归档轨道降低亮度但文字保留对比度。玻璃仅用于顶部工具栏、菜单与展开详情：145° 渐变、白色 .16 边框、inset 高光、16px blur / 108% saturate。其余主谱保持通透。静态 SVG 冷光与极轻噪点背景，不使用视频。

Inter 可变字体本地托管，金额使用 tabular-nums。汇总 0 / 80 / 160ms 入场，轨道从购入端揭示并逐行错开 30ms，总时长约 800ms；展开约 360ms。支持 `prefers-reduced-motion`，数字直接显示实际值。按钮支持键盘，展开区使用 `aria-expanded` / `inert`，弹窗使用原生 dialog，菜单 Escape 可关闭。

## 验证

```bash
npm test                       # 原始算法 / CSV 回归与快照、事件适配测试
npx playwright install chromium # 首次使用 Playwright 时安装浏览器
npm run build
npm run test:e2e                # 启动 4187 端口生产预览并验证浏览器交互
```

可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定已有 Chromium。测试包含逐设备天数与日均、完整数据一致性、改名不影响成本、缺价、续保估算、回收截止、CSV 原文往返、时间谱展开、排行、CRUD / 撤销、导入替换、统计与预测、手机固定列和浅色 / 减少动态效果。

`artifacts/` 提供桌面深浅主题、手机与展开详情的截图。`scripts/screenshots.mjs` 可通过 `SCORE_URL` 指定运行地址重新截图。

## 文件入口

- `index.html` / `src/main.tsx`：页面与 React 入口。
- `src/App.tsx`：页面组织、状态、存储、菜单、导入导出与操作流程。
- `src/components/Score.tsx`：共享时间轴、排序、排行、固定列与展开动画。
- `src/components/ScoreDetail.tsx`：曲线、日期探索、支出节点、预测与目标。
- `src/components/Portfolio.tsx`：全账本趋势与分类统计。
- `src/styles.css`：双主题、响应式布局、动效与对比度。
- `public/atmosphere.svg`：静态背景；`public/fonts/` 含字体授权。
- `dist/index.html`：生产部署入口。

## 布局网格（v2.0.3）

`src/grid.css` 为统一布局层：桌面 ≥1024px 使用 12 栏 / 24px 栏间距，平板 768–1023px 使用 8 栏 / 24px 栏间距，手机 ≤767px 使用 4 栏 / 16px 栏间距。页面最大宽度 1536px，边距按 48 / 32 / 16px 收缩。模块间距以 8px 为基本节奏。

表头与设备行共享列定义、16px 内边距和轨迹边界。桌面详情图表与事件分为 8 / 4 栏；平板与手机纵向排列。手机设备名称和成本各占 2 栏，轨迹占满 4 栏，支持名称换行和年均长金额。
